# AI 设计检查与项目回收站

0.1.6 引入应用前设计检查，0.1.7 补充了户型跨度校准、承重待核实保护和家具通行测试。

## 修改如何进入方案

两种模型接入均读取同一份版本化装修知识、项目的设计范围、现场待确认项，以及包含梁柱、水电、注释、柜体配置的完整场景。模型操作先在内存副本中执行，再用同一套确定性规则比较修改前后。新出现或明显加重的问题返回模型纠正；无法修正时保留原方案，显示具体原因。

API 最多进行 5 轮工具交互；Codex 在首次结果不合格时重试 1 次。通过的家具/材质修改进入现有自动应用流程，墙体/门窗修改仍须在界面确认。应用时服务端复核保存版本和当前项目设置，编辑器在替换真实模型前再检查一次。失败不会制造临时保存或撤销记录。

聊天区的「AI 设计范围」随项目保存：

- 默认「固定户型」，AI 不得改变墙体、节点和门窗。需要改造时，用户可以关闭。
- 解锁后，AI 只能修改明确标为非承重的墙或新设计的隔墙。原有墙体的承重字段缺失、为空，或仅由图片推断为非承重时，相关拆墙、改门窗及移动共用端点的请求都会被拒绝。原结构经核实后，可以在编辑器的「原始结构」阶段标明属性。旧方案中已明确标为非承重且无推断标记的隔墙可继续使用。
- 默认要求普通高柜靠合适墙面。明确需要独立隔断柜时，可开启「允许独立高柜」。碰撞和堵门检查仍生效。
- 这些设置约束 AI；手动编辑仍可进行。「检查方案」同时显示新增规则和原编辑器检查结果。

## 设计规则

| 检查         | 当前行为                                                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 普通门尺寸   | 单扇、子母、双扇平开门分别以 1200、1800、2400 mm 筛查异常宽度；推拉/折叠门按实际门型处理，不套用同一上限                         |
| 新围合空间   | 按墙体识别区域，检查用途标注、可用入口、入户连通关系；长期活动空间缺少对外窗时提示并阻止新增问题，无窗储藏/衣帽等空间区别处理    |
| 门口被挡     | 检查门洞、门两侧各 600 mm 的进出区域和约 2000 mm 内的通行净高。平开门另按实际门高检查门扇活动区，子母门用编辑器中的 2∶1 门扇比例 |
| 房间内通行   | 比较摆家具前后的连续可活动区域。家具将原先相通的两片区域分开时提示，保留可绕行的布置。既有堵塞可通过缩减家具分步改善             |
| 普通高柜位置 | 普通衣柜、书柜、鞋柜及落地高柜按朝向检查背面墙体，门窗不当作可安装的连续墙面；岛台和普通矮家具不套此规则                         |
| 相交和越界   | 检查旋转后的家具外框、墙体、部分固定构件及室内区域。抬高普通落地家具后仍检查其占用高度、相交及顶部超过层高的情况                 |
| 异常设备尺寸 | 洗衣机、烘干机、冰箱和马桶的宽/深小于 250 mm 时拒绝，防止明显通过缩小模型掩盖空间不足                                            |
| 既有问题     | 未改变的问题不阻止无关的换色等操作；不会为了清空警告擅自更改原始户型                                                             |

这些数值是本产品的常见错误筛查条件，**不是施工规范上限或安装合格证明**。规则返回问题 ID、对象 ID、说明和比较值，便于进一步完善测试和定位问题。规则实现见 `src/design-rules.mjs`，知识提示见 `src/design-knowledge.mjs`。

## 从户型图生成

提交导入时，应用先在本地保存底图和空白项目，再启动识别。也可选择「直接在原图描墙」。停止识别、服务中断或两次都缺少可用墙线时，草稿从二维底图打开，可校准尺寸、描墙、查看手绘墙体的 3D 效果或重试。空白草稿在原项目重试。已有描图、校准、对话或方案副本时，可明确选择用原图另建识别项目，保留现有编辑。

填写左右总跨度时，程序按识别到的最左和最右墙中线端点的水平距离定标。图中留白不参与跨度计算，底图、墙和家具中心使用同一坐标变换。识图比例与填写值相差超过 2% 时，待确认项会显示两者。用户仍需对照原图核实两侧墙线。未填跨度时采用图纸标注或模型估算值，估算会列入待确认项。

程序按所选数量生成 1 至 3 套方案。数量不足、方案重复或命中可纠正的布局规则时，会要求模型纠正一次。在等待纠正前，已能建模的结果先存为可编辑 3D 草稿。停止识别也能打开该草稿。各套方案可以单独打开。打开检查列表后，可选「在图中定位」选中相关对象，也可以请 AI 调整。

墙线、房间标注和家具逐项读取。门窗引用缺失墙段或跨越墙段端点时，有效墙体照常进入 3D。这处门窗列入「待定位」，有原图坐标时同时显示编号标记。用户可指定所属墙、位置和尺寸，确认放置后可撤销。没有可用家具布局时仍保留户型结构。

布局检查中的同一规则和同一组对象只展示一次。手动编辑可保存仍有碰撞的布局；AI 修改已有方案时，只有明确参与该操作的规则才审核新增或加重的问题。新设计规则默认仅提示。

## 删除与恢复

项目卡片和编辑器顶部均可删除整个项目。确认框显示名称与方案数量；删除将项目标记为回收站状态，完整保留方案、对话、历史、原图副本及校准信息。首页「回收站」恢复后可继续打开。

删除当前项目会停止 AI 请求、清除待应用提案、完成当前保存并关闭编辑会话。项目每次删除/恢复都会更新生命周期编号；旧会话的自动保存、备注、方案复制和 AI 结果不能写回恢复后的项目。回收站持久化到磁盘，重启后仍可恢复；首次初始化标记避免用户清空项目后重新生成示例。

回收站支持永久删除单个项目和清空回收站，两种操作都需要确认。删除状态可核验的损坏项目仍可清理，归属无法核验的文件会出现在诊断中。模型清理只检查已删除项目用过的附件，确认剩余项目、历史和模型库均无引用后才移除。导入文件的原始路径不会被删除。

## 边界与验证

房间连通分析使用有界栅格，小户型格长为 75 mm，大图自动加粗。房间内通行按约 600 mm 净宽筛查，比对摆放家具前后各至少 1 平方米的活动区能否连通。算法保留栅格定位误差，接近阈值的通道、小空间、床边操作位和轮椅转身仍须逐项核实。门口检查独立进行。

采光检查读取对外窗关系。采光面积、日照、商品型号、水电接口、检修空间与复杂柜体嵌入条件仍依赖实际尺寸和专业核对。

自动测试包含规则反例与合理例、两种模型适配器纠错、识图草稿保留、基础几何验证、编辑器原子应用、删除期间迟到请求和重启恢复。识图草稿回归使用本机模拟模型和合成户型图。早期可复现命令与成品结果见 [0.1.6 本地验收记录](releases/0.1.6-local.md)。
